# Home Dashboard — Dependency Upgrade (v1.14.1)

## Test mode: DEPLOY-FIRST

## Scope

Fix M4 from audit: 14 npm CVEs, most critical:
- `@auth/core` — CVE (critical)
- `fast-uri` — CVE (high)
- `undici` — CVE (high)
- `next` — needs 16.3.1 for XSS/DoS fixes

## Approach

1. `npm audit` — capture baseline.
2. `npm audit fix` (non-breaking auto-updates first).
3. Manually bump `next` from 16.2.2 → 16.3.1 in `package.json`.
4. Manually check `@auth/core`, `fast-uri`, `undici` — if not in `dependencies`, they're transitive. Force via `overrides` in package.json if needed.
5. `npm install` to lock the tree.
6. `npm audit` again — capture post-fix diff.
7. `npm run build` — must succeed. If a breaking change surfaces (Next 16.3 API change, etc), STOP and print QUESTION with the build error.
8. Deploy per DEPLOY-FIRST.

## Files touched

- `package.json` — version bumps + possibly `overrides` block
- `package-lock.json` — regenerated by npm
- `change-tracker.md`, `current-state.md`
- Footer version literal + package.json version field

## Version bump

**1.14.1** (bug — dep updates only, no functional change).

## Build & deploy

1. `git checkout -b dep-upgrade-v1.14.1` (optional; can commit directly to main if AG prefers).
2. Actually — commit directly to main. Runbook says single-commit approach.
3. `npm audit --json > /tmp/audit-before.json`
4. `npm audit fix` — commit output.
5. Manual bumps for `next`, plus check overrides for transitive.
6. `npm install`
7. `npm audit --json > /tmp/audit-after.json`
8. Diff: `diff <(jq '.vulnerabilities' /tmp/audit-before.json) <(jq '.vulnerabilities' /tmp/audit-after.json)`
9. `npm run build` — must pass.
10. Print PASS/FAIL from build.
11. **Do a fuller local smoke test than usual:**
    - `npm run start` in dev, hit `http://localhost:3000/login`, log in, click through main dashboard, edit a bookmark, sign out. If any page 500s, STOP.
12. Commit:
    ```
    chore(deps): v1.14.1 — patch 14 npm CVEs + Next 16.3.1
    ```
13. Push `main` → MTCD deploy. Watch the GitHub Actions build carefully — a Next major-minor bump can surface at build time on the container.
14. If MTCD deploy fails (build error in Actions, container crash-looping): `git revert HEAD && git push`. Print the failure. STOP.
15. If MTCD comes up clean on v1.14.1: **wait 5 minutes**, hit the site manually, check for anything odd. Only then push `abraham-prod`.
16. If abraham deploy fails: revert on abraham branch same way. MTCD stays on v1.14.1 unless Ben says otherwise.
